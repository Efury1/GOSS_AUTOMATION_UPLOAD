Help: Upload CSS to iCM

Contents

What it does

It uploads each site's built CSS file to GOSS iCM for you, so you don't have to open every site's CSS item and upload it by hand.

For every site you tick, it:

  1. finds the site's CSS item in iCM Media,
  2. uploads the CSS file from your sites folder,
  3. saves it, adding your version note if you typed one.

You choose the environment (Development, Test, Preprod or Live), the browser, and the sites. You log in to iCM yourself; it never knows your password.

Setting it up (once)

You need Node.js 20 or newer, and Microsoft Edge or Google Chrome.

  1. Put the goss-upload folder next to GOSS-skin, for example both inside Repos.
  2. In the goss-upload folder, run npm install once.
  3. Open it. The first time, a Settings box asks for the sites folder, the iCM links and the browser, and saves them (see Settings).
  4. Make the Upload CSS desktop shortcut. The steps are in README.md in the goss-upload folder.

The goss-upload folder should look like this:

goss-upload\
  upload-css.js      does the uploading
  .env               your settings
  picker\            this window
  report\            the layout of failure pictures
  screenshots\       failure pictures (appears when needed)

The sites folder

The sites folder is the folder that holds one folder per site. Normally it's GOSS-skin\global\sites. Pick that folder, not a single site's folder.

Inside it, each site needs:

  • its own folder, named after the site, like tolhouse-gaol;
  • a CSS file inside with exactly the same name, plus .css.
sites\
  american-library\
    american-library.css      ✓ listed
  tolhouse-gaol\
    tolhouse-gaol.css         ✓ listed
  devolution\
    styles.css                ✗ not listed: wrong file name
  old-site\
    (no .css file)            ✗ not listed: not built

Only sites with a correctly named CSS file appear in the list. If a site is missing, check the folder and file names match, and that the CSS has been built.

Matching the site to iCM

The folder name is matched to the CSS item's name in iCM Media, ignoring capitals, spaces, dashes, and the words DEV, TST, PRP, PRD and CSS. So the folder american-library matches the iCM item American Library - DEV - CSS.

If a site's iCM name is too different (for example the folder is recycles but iCM calls it Norfolk Recycles), it needs adding to ALIASES in upload-css.js.

What goes in the CSS file

Each <site>.css must be the finished, built CSS for that site: the file GOSS-skin's build produces.

  • Build it first. Run the GOSS-skin build so the file has your latest changes. It uploads whatever is in the file at that moment.
  • The whole stylesheet, not just your changes. The upload replaces the file in iCM completely. Anything not in your file is gone from that site.
  • Plain CSS only. Not SCSS/Sass, not partials, not files that need building. iCM serves the file exactly as it is.
  • Keep the name the same as the folder (tolhouse-gaol.css).
  • Check links inside the CSS, like images and fonts in url(...). They must point to places that exist on the website, because only the CSS file is uploaded, not the images or fonts it mentions.

Tip: upload to Development or Test first, check the site looks right, then do Preprod and Live.

How to run it

  1. Build the CSS in GOSS-skin.
  2. Double-click Upload CSS on the desktop. (Or in a terminal in the goss-upload folder: npm start, or ./run in Git Bash.)
  3. In this window: check the sites folder, pick an environment and browser, and tick the sites.
  4. Click Start upload. For Live, click it twice to confirm.
  5. Log in to iCM in the browser that opens. It deals with the "already logged on" warning and the security questions note by itself, then starts.
  6. Leave the browser alone while it works. The black window shows each step and OK or FAIL for each site.
  7. When it's finished, press Enter in the black window to close the browser.

From a terminal, without this window

npm run upload:dev -- all uploads every site to Development. Add --note "text", --significant or --browser chrome if needed.

Using this window

  • Environment: click one. Live is red and needs two clicks on Start.
  • Open iCM in: Edge or Chrome. A browser that isn't installed is greyed out. Your choice is remembered.
  • Sites folder: Browse… to pick a different folder (double-click to open folders, then OK), or paste a path and press Enter. Remembered for next time.
  • Find site (Ctrl+F): type part of a name to narrow the list. Select all, Select none and Fill blanks only change the sites showing.
  • Tick boxes: only ticked sites are uploaded. All start ticked.
  • The × in the blue title bar closes without uploading anything.

Version notes and Significant

When a site is saved, iCM shows a Version Control box. It fills that box in for you:

  • Note: type one next to a site to have it saved in iCM's version history. Leave it blank to save with no note.
  • Significant: tick it to mark that update as a significant change.
  • Same note for all: type a note (and tick Significant if you want), then click Fill blanks. It fills every ticked site that's showing and has no note yet.

Then it presses Update. If the box won't close, it cancels it so the next site isn't blocked, and that site shows as FAIL.

Environments

  • Development (dev) and Test (tst): safe places to try changes.
  • Preprod (prp): the last check before live.
  • Live (prd): the real websites the public sees. Upload here only when you've checked the change on another environment.

Each environment's iCM link comes from .env.

What it does in iCM

  1. Opens the iCM login page and waits for you to log in.
  2. Opens Content › Media, then the folder Shared resources › Developer › Front end - CSS-JS › dynamic.
  3. For each site: double-clicks its CSS item, opens the Files tab, uploads the CSS file, and presses Save this media.
  4. Fills in the Version Control box and presses Update.
  5. Goes back to the list and does the next site.

It handles iCM's pop-up notes along the way, like the image format note and the spell checker.

If something goes wrong

A picture is saved in the screenshots folder inside goss-upload, named with the date, time and site. The top says what went wrong and which step it was on; underneath is what the browser was showing. The other sites still carry on.

Common messages

  • No CSS item in iCM matches: iCM's name for the site is too different from its folder name. See The sites folder.
  • The Version Control box stayed open: iCM wanted something else filled in. Try again with a note.
  • Couldn't start Google Chrome (or Edge): that browser isn't installed. Pick the other one.
  • … is missing from .env: a setting is missing. See Settings.
  • No sites here: the sites folder is wrong, or the CSS hasn't been built.

Still stuck? See Reporting a problem.

Settings (.env)

The easiest way to change them is Settings… in this window's menu. The first time it's run, the Settings box opens by itself.

They're saved in the .env file in the goss-upload folder. Every one is needed except BROWSER; if one is missing it stops and says which. Don't put passwords in it.

SITES_DIR=../GOSS-skin/global/sites
ICM_DEV_URL=https://ncc1-dev.gosshosted.com/...
ICM_TST_URL=https://ncc1-tst.gosshosted.com/...
ICM_PRP_URL=https://ncc1-prp.gosshosted.com/...
ICM_PRD_URL=https://ncc1-prd.gosshosted.com/...
BROWSER=msedge
LEARN_MODE=false
  • SITES_DIR: the sites folder. A full path, or relative to goss-upload. Changing it in this window updates it for you.
  • ICM_…_URL: the iCM login page for each environment.
  • BROWSER: msedge or chrome. Optional: leave it out and pick the browser in this window instead. Picking one here updates it for you.
  • LEARN_MODE: true uploads the first ticked site only and saves extra pictures, for testing. Normally false.

Reporting a problem

Report problems, or ask for changes, on GitHub:

github.com/Efury1/GOSS_AUTOMATION_UPLOAD

  1. Open the link above and go to the Issues tab.
  2. Click New issue.
  3. Give it a short title, like "tolhouse-gaol fails at Version Control on Test".

What to include

  • What you were doing: environment, browser and which sites.
  • What happened, and what you expected to happen.
  • The failure picture from the screenshots folder (drag it into the issue).
  • The text from the black window: select it, copy, and paste it into the issue.

Don't include passwords or anything private. Check the pictures don't show anything that shouldn't be shared.
